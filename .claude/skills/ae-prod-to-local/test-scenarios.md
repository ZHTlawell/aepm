# ae-prod-to-local 测试场景

## 场景 1：标准 iOS + Java 后端项目本地化
- **用户说**："帮我把这个代码在本地跑起来"
- **预期行为**：agent 扫描项目结构，提取全量依赖，做三档分类（公司独有/可替代/通用），产出 dependency-map.md + local-run-guide.md + team-request.md
- **验证标准**：依赖分类表覆盖所有依赖项，每项有分类理由

## 场景 2：私有 Maven 仓库不可达
- **用户说**："本地跑不起来"（依赖公司私有 Maven）
- **预期行为**：识别出私有仓库地址，归为"公司独有"，在 team-request.md 中列出需要的权限或 jar 包
- **验证标准**：不尝试绕过私有仓库，精确列出需求

## 场景 3：只有配置仓库无源码
- **用户说**："这个 repo 里都是配置文件"
- **预期行为**：识别为配置仓库，分析其依赖的其他服务，列出需要的关联仓库
- **验证标准**：不尝试构建，正确识别仓库角色

## 场景 4：核心链路不明确
- **用户说**："帮我跑通这个项目"（未说明产品做什么）
- **预期行为**：主动询问产品简介，或从代码推断核心链路，与用户确认范围
- **验证标准**：不盲目尝试跑通所有功能

## 场景 5：产出约束供 ae-dev 使用
- **用户说**："分析完了，帮我整理成 ae-dev 可用的约束"
- **预期行为**：从 dependency-map.md 提炼约束条目，输出 constraints-draft.md
- **验证标准**：约束条目包含 Detection Rules 和 Enforcement Level
