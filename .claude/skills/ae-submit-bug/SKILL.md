# Skill: 提交 Bug (submit-bug)

## 触发条件

当用户报告 bug、描述异常行为、或说"帮我提一个 bug"时触发。

## 核心原则

**让用户用最少的话把问题说清楚。** 不要一次问完所有问题，根据用户已提供的信息跳过已知项。

## 执行流程

### Step 1: 收集 bug 信息

与用户对话，逐项厘清以下信息：

#### 1a. 问题描述
- 发生了什么？
- 涉及什么产品/工具/项目？

#### 1b. 截图（如有）

如果 bug 涉及 UI 表现，询问用户是否有截图：
> "能截个图给我看看吗？这样 AE Team 能更快定位问题。"

如果用户无法提供截图，在 issue 中标注 `无截图，需人工复现`。

#### 1c. 具体化

如果用户的描述很笼统（如"用不了"、"有问题"），追问具体表现：
> "能具体说说是哪个环节出了问题吗？比如点了什么按钮、看到了什么错误？"

### Step 2: 格式化

将收集到的信息整理为 markdown：

```markdown
## 描述
<!-- 一句话说清问题 -->

## 具体表现
1. ...
2. ...

## 复现步骤
1. ...
2. ...

## 期望行为
<!-- 应该是什么样的 -->
```

### Step 3: 用户确认

将格式化后的标题和正文展示给用户确认。

标题格式：`[BUG] 产品名 — 问题简述`

### Step 4: 提交

**确定目标仓库：** 读取已安装的 AE 角色 CLAUDE.md（路径为 `~/.ae/go/.claude/CLAUDE.md` 或 `~/.ae/pm/.claude/CLAUDE.md`，**不是当前 workspace 的 CLAUDE.md**）中的「Issue 路由」表，获取目标仓库名。

```bash
ae git issues create --repo <目标仓库> --title "[BUG] 标题" --body "正文"
```

### Step 5: 确认结果

向用户展示 issue 链接：
> "Bug 已提交，AE Team 会跟进处理。你可以在这个链接查看进展。"

## 重要规则

- **提交前必须让用户确认内容**
- 笼统描述必须追问具体化
- 多个 bug 逐个提交，每个一个 issue
