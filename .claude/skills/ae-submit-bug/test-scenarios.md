# ae-submit-bug 测试场景

## 场景 1：完整 bug 报告流程
- **用户说**："有个 bug，ae update 跑完提示成功但版本号没变"
- **预期行为**：Agent 收集问题描述后追问复现步骤和验证标准，查重现有 issue，格式化为标准模板，让用户确认后提交，验证 issue 创建成功
- **验证标准**：issue 包含复现步骤和验证标准；提交后能在 Gitee 找到

## 场景 2：笼统描述追问具体化
- **用户说**："ae-pm 有问题，用不了"
- **预期行为**：Agent 不直接提交，而是追问："能具体说说是哪个环节出了问题吗？"直到收集到可执行的复现步骤
- **验证标准**：至少追问一轮才进入格式化阶段

## 场景 3：查重发现相似 issue
- **用户说**："截图功能不好使，帮我提个 bug"
- **预期行为**：Agent 执行查重，发现已有类似 issue，询问用户是补充评论还是新开
- **验证标准**：展示了相似 issue 信息；根据用户选择执行

## 场景 4：验证标准为空拒绝提交
- **用户说**："提交吧，验证标准不用写了"
- **预期行为**：Agent 拒绝提交，解释验证标准是必填项，主动草拟验证标准让用户确认
- **验证标准**：不提交空验证标准的 issue

## 场景 5：多个 bug 拆分提交
- **用户说**："有两个问题，一个是截图保存失败，另一个是 OCR 中文识别不准"
- **预期行为**：Agent 告知会拆分为两个独立 issue，分别收集信息、确认、提交
- **验证标准**：创建了两个独立 issue，各自有完整描述和验证标准
