# ae-submit-requirement 测试场景

## 场景 1：完整需求提交流程
- **用户说**："我希望 agent 能自动帮我跑每日站会总结"
- **预期行为**：Agent 收集核心诉求、当前手动做法、期望效果和验证标准，查重后格式化为标准需求模板，用户确认后提交
- **验证标准**：issue 包含使用场景、当前做法和至少 2 个验证场景

## 场景 2：用户说不清验证标准
- **用户说**："我想要一个能帮我管理任务的功能"
- **预期行为**：Agent 追问后用户仍说不清，Agent 根据诉求草拟 2-3 个验证场景让用户确认或修改
- **验证标准**：Agent 主动草拟了具体验证场景

## 场景 3：查重发现相似需求
- **用户说**："我想让 agent 能读飞书文档"
- **预期行为**：Agent 查重发现相似需求，展示给用户，让用户选择补充或新建
- **验证标准**：展示了相似 issue 信息；根据用户选择执行

## 场景 4：需求跨多个能力拆分
- **用户说**："我希望 agent 能从飞书读消息、整理成周报、然后发到群里"
- **预期行为**：Agent 识别出涉及多个独立能力，建议拆分为独立需求分别提交
- **验证标准**：每个拆分后的 issue 有独立的验证标准

## 场景 5：Agent 不替用户做技术方案
- **用户说**："我想要自动部署功能，最好用 Docker + K8s"
- **预期行为**：Agent 收集需求时不在 issue 中写技术方案，只描述用户诉求和验证标准
- **验证标准**：issue 正文只包含需求描述和验证标准，不包含技术方案
