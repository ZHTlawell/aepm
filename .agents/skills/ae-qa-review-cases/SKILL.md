# Skill: 测试用例审核评分

## 触发条件

当用户要求审核测试用例、检查用例质量、给用例打分、review 测试用例，或用例生成后需要进入人工确认/落库前的质量门禁时触发。

## 输入

- 测试用例草案、已确认用例或用例库导出。
- 可选：PRD、产品图、接口文档、数据库说明、历史 Bug、测试报告。
- 可选：`.qa-memory/`、`qa/01-product-brief.md`、`qa/02-module-map.md`、`qa/03-user-journeys.md`、`qa/06-risk-map.md`。

## 执行流程

1. 读取 `constraints/test-case-standard.md`。
2. 先引导用户确认是否进行测试用例质量审核，不要直接执行完整审核。
3. 用户确认后，解析每条测试用例：
   - 用例 ID
   - 标题/场景
   - 优先级
   - 前置条件
   - 测试数据
   - 操作步骤
   - 预期结果
   - 来源
   - 自动化建议
4. 解析 PRD、QA Memory 或产品资料，建立需求点/模块/风险点列表。
5. 将每条用例映射到需求点、模块、用户路径或风险点。
6. 按 100 分制逐条评分。
7. 标记通过状态：
   - `passed`: 总分 >= 60
   - `failed`: 总分 < 60
8. 对低于 60 分的用例输出扣分原因和修改建议。
9. 输出整体覆盖分析和共性问题。
10. 审核完成后，只引导一个下一步：让用户修复不通过用例，或确认通过用例进入落库。

## 引导话术

审核前默认只引导一个动作：

```text
已发现测试用例草案。

下一步只做一件事：请确认是否进行测试用例质量审核。

审核会按 100 分制检查逻辑完整性、预期结果、前置条件、需求覆盖和边界异常。低于 60 分的用例不能确认、落库或进入自动化评审。
```

## 评分维度

| 维度 | 满分 | 评分标准 |
|------|------|----------|
| 逻辑完整性 | 25 | 步骤清晰、无跳步、可重复执行、步骤与预期结果对应 |
| 预期结果明确性 | 20 | 预期结果可验证，无“正常显示”“成功”等模糊表述 |
| 前置条件完备 | 15 | 环境、账号、数据、权限、开关等前置条件明确 |
| 需求/风险覆盖度 | 25 | 用例能映射到 PRD、QA Memory、风险地图或历史 Bug |
| 边界/异常覆盖 | 15 | 覆盖边界值、异常路径、错误处理或状态流转 |

## 通过规则

- 总分低于 60 分的用例不能进入 `approved`。
- 总分低于 60 分的用例不能进入落库。
- 总分低于 60 分的用例不能进入自动化用例评审。
- 如果缺少 PRD 或 QA Memory，需求/风险覆盖度必须降级为“用例是否体现明确需求场景”，并标注依据不足。
- 审核报告默认写入 `qa/10-test-case-review.md`，不要直接写入 `.qa-memory/`，除非用户确认要沉淀审核结论。

## 硬规则

- 不能为了让用例通过而替用户补全事实。
- 不能把 `inferred` 依据当成 `confirmed`。
- 对模糊预期结果必须扣分，例如“正常显示”“操作成功”“符合预期”。
- 审核完成后，每轮只引导一个下一步。
- 未经用户确认，不要直接执行完整用例审核。
