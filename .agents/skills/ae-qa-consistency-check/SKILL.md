# Skill: QA 资料一致性检查

## 触发条件

当项目已完成初步入驻，需要发现资料冲突、覆盖缺口或实现与需求不一致时触发。

## 检查维度

- PRD 有功能，但测试用例没有覆盖。
- 产品图有入口，但 PRD 未定义业务规则。
- API 文档有接口，但页面或流程中没有入口。
- 数据库存在状态字段，但 PRD 未说明状态流转。
- 历史 Bug 高频模块，但回归用例不足。
- 自动化覆盖路径与当前产品路径不一致。
- 测试报告遗留风险没有对应跟踪项。

## 执行流程

1. 读取 `qa/` 和 `.qa-memory/`，没有则先建议执行 `/ae-qa-onboard-project`。
2. 扫描产品文档、产品图、API、DB、用例、Bug、报告、自动化。
3. 建立“功能项 -> 页面 -> API -> 数据 -> 用例 -> Bug -> 自动化”的映射。
4. 输出冲突、缺口和待确认项。

## 输出

写入 `qa/11-consistency-check.md`：

```markdown
# 资料一致性检查

## 冲突清单

| ID | 类型 | 描述 | 证据 A | 证据 B | 影响 | 建议处理 |
|----|------|------|--------|--------|------|----------|

## 覆盖缺口

| 功能 | 缺口 | 风险 | 建议补充 |
|------|------|------|----------|

## 待确认问题
```

## 硬规则

- 不要替产品或开发“自动选择正确版本”，只列出冲突和影响。
- 每个冲突必须至少有两个来源或一个来源加一个缺失证据。
