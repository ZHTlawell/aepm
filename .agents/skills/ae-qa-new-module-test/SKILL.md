# Skill: 新模块测试任务规划

## 触发条件

当用户提供新模块、新需求、PR、版本说明或测试任务，希望产品专属 QA Agent 基于已有产品理解进行测试任务拆解时触发。

## 输入

- 新模块说明、需求文档、PRD、设计图、接口文档、Git diff 或自然语言描述。
- `.qa-memory/` 中的产品记忆。

## 前置检查

1. 读取 `constraints/product-agent-memory.md`。
2. 检查产品熟悉度是否达到 85。
3. 如果未达到 85，先追问缺失信息，不要直接生成完整测试任务。
4. 检查新模块是否属于当前产品。
   - 如果属于另一个产品，提示创建新的产品 Agent。

## 执行流程

1. 基于 `.qa-memory/` 理解新模块与现有产品的关系。
2. 识别影响范围：
   - 页面
   - 模块
   - 用户路径
   - API
   - 数据状态
   - 权限
   - 历史风险
   - 自动化覆盖
3. 如果信息不足，按追问策略向用户提问。
4. 生成“可选择的测试任务清单”，让用户选择要执行的任务。
5. 用户选择后，再执行对应任务，不要默认全部展开。

## 输出任务清单

输出 `qa/14-new-module-test-plan.md`：

```markdown
# 新模块测试任务清单

## 新模块理解摘要

## 与现有产品的关系

## 需要用户选择的测试任务

| 编号 | 任务 | 产物 | 建议优先级 | 适用场景 |
|------|------|------|------------|----------|
| 1 | 生成模块测试范围 | 测试范围清单 | P0 | 需求刚确定 |
| 2 | 生成 P0/P1/P2 用例 | 测试用例 | P0 | 准备执行测试 |
| 3 | 生成接口测试点 | 接口检查清单 | P1 | 有 API 文档 |
| 4 | 生成数据/数据库检查点 | 数据一致性清单 | P1 | 涉及状态流转 |
| 5 | 生成回归范围 | 回归清单 | P0 | 修改已有流程 |
| 6 | 生成测试数据准备清单 | 测试数据 | P1 | 需要账号/配置 |
| 7 | 生成自动化候选 | 自动化建议 | P2 | 稳定路径 |
| 8 | 生成缺陷观察点 | 风险观察清单 | P1 | 高风险模块 |
```

## 硬规则

- 先让用户选择任务，再执行。
- 不熟悉时必须追问，追问目标是补足模块理解。
- 所有测试任务必须引用产品记忆或新模块资料作为来源。
