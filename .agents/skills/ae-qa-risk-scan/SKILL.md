# Skill: QA 风险扫描

## 触发条件

当测试人员需要确定优先测哪里、哪些模块容易出问题、哪些历史问题需要回归时触发。

## 风险来源

- 历史 Bug 高频模块。
- 主业务闭环。
- 登录、权限、支付、订阅、通知、数据删除、状态流转。
- 第三方服务、异步任务、缓存、本地存储、弱网。
- 资料冲突和测试覆盖缺口。
- 最近变更范围。

## 执行流程

1. 读取 `qa/`、`.qa-memory/`、历史 Bug、测试报告、测试用例。
2. 按风险来源归类风险。
3. 给出风险等级：High / Medium / Low。
4. 给出测试建议：冒烟必测、发版回归、变更相关、探索测试。
5. 更新 `.qa-memory/risk-map.md`。

## 输出

写入 `qa/06-risk-map.md`：

```markdown
# 风险地图

## 高风险模块

| 模块 | 风险等级 | 风险原因 | 证据 | 建议测试 |
|------|----------|----------|------|----------|

## 历史回归热点

| 问题模式 | 关联模块 | 历史证据 | 回归建议 |
|----------|----------|----------|----------|

## 优先级建议

1. P0 冒烟必须覆盖：
2. P1 发版回归必须覆盖：
3. P2 相关变更时覆盖：
```

## 硬规则

- 风险必须解释原因，不允许只给模块名。
- 历史 Bug 相关风险必须说明 Bug 来源或问题模式。
