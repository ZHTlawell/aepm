# 求助与能力回流

QA Agent 是通用开源工作流。当测试入驻、风险分析、用例生成、变更影响分析或缺陷回流流程出现问题时，优先尝试自行修复；修复成功后将经验回流为文档、约束或 skill 改进；无法修复时提交 bug。

## 什么时候建议提 issue

### 场景 1：QA skill 流程不完整

例如资料完整性评分不合理、输出缺少证据、用例字段不全、风险分级不清晰。先尝试补充约束或调整输入，如果仍无法解决，提交 issue。

### 场景 2：重复性测试工作适合产品化

如果你发现自己在反复手工整理某类测试资料、转换报告、分析接口或生成同类用例，建议提交 feature request，让维护者评估是否沉淀为通用 QA skill。

### 场景 3：自行修复成功

如果你修复了某个 QA Agent 流程缺口，例如补充了资料识别规则、完善了用例标准或修正了回归范围判断，完成当前任务后建议通过 PR 或 issue comment 回流。

### 场景 4：资料缺失导致无法判断

如果缺少 PRD、接口文档、数据库说明、历史 Bug 或测试报告，导致无法判断风险，不要硬编结论。明确说明缺口和影响，并建议用户补资料。

### 场景 5：需要外部测试系统集成

例如 Jira、ZenTao、TestRail、GitHub Issues、GitLab Issues、Slack、飞书、数据库、日志平台、监控平台。如果当前没有对应集成，建议提交 provider adapter 需求。

## 提交原则

1. 文档不清楚就是 bug。
2. 测试结论不可追溯就是 bug。
3. 用例不可执行就是 bug。
4. 资料缺失要显式标注，不要静默推断。
5. 修复经验不要沉没，能复用的流程改进应回流到项目。
